# 제목, 썸네일, 본문 이미지

홈피드에서 독자가 보는 것은 썸네일과 제목 두 가지뿐이다. 눌릴지 말지는 여기서 정해진다. 다만 썸네일 규격·글자 수·제목 길이에 대한 네이버 공식 기준은 확인된 것이 없다(`naver.md`). 아래 수치는 출발값이고, 실제로 무엇이 통하는지는 `log/posts.md`에 쌓이는 기록으로 판단한다.

## 제목

후보를 3개 내고 그중 하나를 추천한다. 셋은 서로 다른 방식이어야 고르는 의미가 있다. 낱말만 바꾼 셋은 내지 않는다.

제목이 궁금증을 만드는 방식은 대략 이렇다(모양을 보여 주는 예이고 사실 주장이 아니다).

- 같이 나오기 어려운 두 사실을 붙인다 — "보험료는 올랐는데 돌려받는 돈은 줄었다"
- 같아야 할 것이 다르다 — "같은 평형인데 관리비는 두 배였다"
- 결과만 보여 주고 원인을 남긴다 — "수출이 늘어난 달에 무역수지는 적자였다"
- 구체적인 숫자 하나를 세운다 — "한 달 ○만 원 차이가 30년이면 ○천만 원이었다"

지킬 것:

- 본문이 제목을 문자 그대로 증명해야 한다. 제목이 본문보다 한 걸음 더 나가면 낚시다. 누르고 바로 나가는 독자는 수익에도 다음 노출에도 도움이 되지 않는다.
- 답을 다 말하지 않는다. 다 말한 제목은 누를 이유가 없다.
- 핵심은 앞쪽 20자 안에 둔다. 피드에서 뒤가 잘려도 뜻이 통하게.
- 심기로 한 검색어를 자연스럽게 넣는다. 검색어 때문에 문장이 딱딱해지면 사건을 앞에 두고 검색어를 뒤에 붙인다.
- "오늘", "어제", "이번 주"를 쓰지 않고 날짜를 쓴다. 발행이 하루 밀려도 틀리지 않고, 나중에 검색으로 들어온 사람에게도 맞는다.
- 쓰지 않는 말: 총정리, 알아보기, 완벽 정리, 충격, 모르면 손해, 반드시. "진짜 이유"는 본문이 원인을 실제로 증명할 때만.
- 물음표로 끝나는 제목은 셋 중 하나까지.

## 썸네일

정사각형 1080×1080 한 장. `assets/thumb.html`을 복사해 문구만 바꿔 쓴다.

- 글자는 한 줄에 한글 8자 안팎, 많아야 두 줄. 틀의 글자 크기에서 한 줄에 들어가는 양이 그 정도다. 숫자와 기호는 한글보다 좁지만, 넘치면 글자를 줄이지 말고 말을 줄인다. 여기에 큰 숫자 하나를 더할 수 있다.
- 썸네일은 제목을 되풀이하지 않는다. 썸네일이 "응?"을 만들고, 제목이 무슨 이야기인지 알려 주는 짝으로 만든다.
- 썸네일에는 조건을 달 자리가 없다. 그래서 숫자를 세울 때는 조건 없이도 참인 숫자를 쓰거나, 조건을 가리키는 낱말을 같이 넣는다("6개월 변동이면"). 일부에게만 맞는 숫자를 모두에게 해당하는 것처럼 보이게 두지 않는다.
- 만든 뒤 가로 320px로 줄인 사본을 직접 열어 본다. 피드에서는 그쯤 크기로 보인다.
- 모든 글의 썸네일이 같은 틀이어야 피드에서 "그 블로그"로 알아본다. 색과 배치를 글마다 새로 짓지 않는다.

## 본문 이미지 3~5장

이미지 한 장은 글의 덩어리 하나를 눈으로 보여 주는 것이다. 장식으로 넣지 않는다. 글을 다 쓰고 "어디에 그림을 넣을까"를 찾지 말고, 뼈대 단계에서 "이 덩어리는 그림이 더 빠르다"를 정한다.

잘 맞는 것:

- 계산 카드 — 조건, 식, 결과를 한 장에
- 비교 막대 — 둘이나 셋의 차이
- 날짜 순서 — 발표일, 반영일, 납부일 같은 흐름
- 짧은 표 — 조건별 결과
- 선 그래프 — 시간에 따른 변화. 실제 데이터로만 그린다

지킬 것:

- 무료 스톡 사진, AI로 만든 실사 이미지는 쓰지 않는다. 예전 글이 스톡 사진을 썼고, 누구나 같은 사진을 쓴다. 이미지는 이 글만의 작업이 보이는 자리다.
- 이미지 속 숫자는 숫자 장부에서 복사한다. 새로 타이핑하지 않는다.
- 이미지가 말하는 결론(한 문장과 주인공 숫자)은 본문에도 글로 쓴다. 검색은 글자를 읽고, 이미지가 안 뜨는 독자도 있다. 다만 표나 순서 카드의 줄을 본문에 전부 다시 옮기지는 않는다. 같은 내용이 두 번 나오면 읽는 사람이 지친다.
- 이미지 아래쪽에 출처를 짧게 적는다(기관·자료·기준일).
- 오름은 빨강, 내림은 파랑으로 쓰고 `+`/`−`나 ▲▼를 함께 쓴다.
- 강조는 한 장에 한두 곳만. 그라데이션, 이모지 아이콘, 번쩍이는 효과는 쓰지 않는다.
- 색·글꼴·굵기는 틀의 것을 그대로 쓴다. 다른 디자인 지침과 부딪히면 이 틀이 우선이다. 글마다 달라지면 블로그의 얼굴이 흩어진다.
- 선 그래프는 선을 두 개까지만 그리고, 범례 대신 선 끝에 이름을 직접 붙이고, 값 라벨은 말하려는 지점 서너 곳에만 단다.
- 렌더한 PNG는 반드시 열어서 본다. 잘린 글자, 선과 겹친 라벨, 두 줄로 꺾인 출처 줄, 네모로 깨진 한글을 찾는다. 하나라도 있으면 고쳐서 다시 뽑는다.

## 만드는 법

`assets/thumb.html`(썸네일)과 `assets/card.html`(본문 카드)을 작업 폴더에 복사해 문구를 바꾸고, `scripts/render.cjs`로 PNG를 뽑는다. 스크립트는 이 스킬 폴더에 있는 것을 경로로 불러 쓴다.

```bash
node <스킬 폴더>/scripts/render.cjs thumb.html 01_thumb.png --w 1080 --h 1080
node <스킬 폴더>/scripts/render.cjs card.html 02_calc.png --w 1080          # 높이는 내용에 맞춰 자동
node <스킬 폴더>/scripts/render.cjs thumb.html thumb_320.png --w 1080 --h 1080 --scale 0.2963   # 320px 확인용
```

- 기본은 2배 해상도로 뽑는다(1080 지정 시 2160px). `--scale`로 바꾼다.
- 한글 글꼴(Pretendard)은 `assets/fonts/`에 들어 있고 스크립트가 알아서 끼워 넣는다. 따로 설치할 것이 없다.
- 카드 틀에는 계산·막대·순서·표·선 그래프 블록이 들어 있다. 한 장에 하나만 남기고 나머지는 지운다.

선 그래프는 `scripts/linechart.py`가 SVG를 만들어 준다. 값을 JSON으로 주면 카드의 그래프 블록에 그대로 넣을 SVG가 나온다.

```bash
python3 <스킬 폴더>/scripts/linechart.py chart.json > chart.svg
```

```json
{
  "x": ["1월", "2월", "3월", "4월", "5월", "6월"],
  "x_every": 1,
  "decimals": 2,
  "series": [
    {"name": "가 지표", "values": [2.89, 2.77, 2.82, 2.81, 2.89, 2.90], "hero": true, "label": [0, 5]},
    {"name": "나 지표", "values": [2.50, 2.50, 2.50, 2.75, 2.75, 3.00], "step": true, "label": [0, 5]}
  ]
}
```

`hero`는 주인공 선(짙은 색, 점 표시), `step`은 계단식으로 바뀌는 값(정책금리, 요금처럼), `label`은 값 라벨을 달 지점의 순번이다. 값은 장부에서 복사한다. 라벨이 겹치면 `label` 지점을 줄이거나 옮긴다.

카드 틀의 색과 글꼴은 `assets/` 파일 맨 위 `:root` 변수에 모여 있다. 바꿀 일이 있으면 거기서 한 번에 바꾼다.
